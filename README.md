# 写作台

**本地优先的中文小说写作工作台。** 稿件是你电脑上的普通 Markdown 文件，不联网、不上传、不调用 AI。

面向中文小说作者（网文连载为主，兼顾出版向）。跑在浏览器里，服务在你本机。

[![CI](https://github.com/shuaixing2020-ux/writing-desk/actions/workflows/ci.yml/badge.svg)](https://github.com/shuaixing2020-ux/writing-desk/actions/workflows/ci.yml)

## 为什么做这个

写长篇时，工具选型的风险不在功能多少，而在两件事：**稿件会不会丢**、**十年后还能不能打开**。

现有工具的问题：

- **云写作平台**：断网就写不了，平台改规则你的稿子就受限，导出还要付费
- **桌面软件**（novelWriter、Manuskript）：成熟，但绑定桌面，手机上写不了
- **通用笔记软件**：没有卷章结构、没有设定库，字数口径和发布平台对不上

写作台的选择是：**正文存成普通 Markdown 文件**，数据库只是加速索引，删了能重建。
所以你随时可以带着文件夹走，用任何编辑器打开，用 Git 管理，或者只是拷到 U 盘。

## 核心特性

### 稿件永不丢（最高优先级）

- **原子写**：写同目录临时文件 → fsync → rename 覆盖。断电或崩溃时，文件要么是旧版本、要么是新版本，永不半写
- **自动保存**：停止输入 2 秒后保存；切换章节、切走窗口、关闭页面立即保存
- **本地草稿兜底**：未确认保存的内容先写进浏览器本地，服务重启或浏览器崩溃后能恢复
- **保存失败不静默**：状态栏红字 + 提示 + 指数退避自动重试
- **冲突不覆盖**：多标签页同时改同一场景时，落后的版本另存为冲突副本，由你选择保留哪一版

### 中文写作优化

- **输入法兼容**：拼音组字期间不触发保存与检查，不吞字、不跳光标
- **字数口径三档**：仅汉字 / 汉字+标点 / 平台口径，状态栏常显；全书统计、每日目标、导出报告共用同一处实现
- **中文搜索**：逐字索引 + 锚点校验，两个字的人名（如「林远」）也能搜到 —— FTS5 的 trigram 分词器做不到这点
- **中文排版**：段首缩进用样式实现（不往正文塞空格），字号、行距、版心宽度、字体（衬线/无衬线）可调
- **标点自动规整**（可选，默认关闭）：保存时把 `...` `。。。` 规整为 `……`、`--` 规整为 `——`、折叠重复的 `！？`、把中文语境里的半角标点转全角。只在保存时做，不打断你正在敲的字；幂等，不会越改越乱
- **规则检查**（11 条内置规则，不依赖 AI）：引号配对（含嵌套错位）、省略号/破折号写法、重复标点、全半角混用、中文间多余空格、常见错别字、相邻重复词、连续相同句首、段落过长、对白引号风格混用。每条规则可单独开关，结果可逐条忽略

### 结构化写作

- 卷 → 章 → 场景三级结构，拖拽排序、折叠、状态流转（构思 / 草稿 / 修改中 / 定稿 / 已发布）
- 大纲视图，每个单元可写摘要，显示字数与状态
- 设定库：角色、地点、势力、物品、术语、事件六类，支持别名
- **出场识别**：正文里的名称（含别名）自动识别，条目页显示「出现在哪些章节、几次、最近一次在哪」
- 出场条目可点击，直接跳到正文命中位置

### 版本与安全

- 内容寻址快照：相同内容只存一份（gzip 压缩去重），改十个字只多存一份压缩全文
- 自动快照（同一场景 5 分钟内节流）+ 重大操作前快照（导入前、删除前、恢复前、冲突时）
- 快照与当前版本的段落级 + 字符级差异对比
- 恢复到任意历史版本；恢复前会先给当前版本存一份，恢复错了也能退回来
- 删除进回收站，保留 30 天，可恢复到原位置
- **定时整项目备份**（tar.gz，系统自带 `tar` 可直接解压）：按每个备份目标的间隔自动运行，也可手动触发；保留份数轮转

### 导入导出

- 导入：txt / md，自动切章（识别「第X章 / 第X节 / 第X回 / Chapter N / 数字行 / Markdown 标题」），**先预览确认再写入**；编码会检测并如实报告（非 UTF-8 的 GBK 文本会被识别为乱码并提示另存为 UTF-8，不会把乱码悄悄写进稿件）
- 导出：txt（可套用平台排版预设：段首缩进、段间空行、章节标题格式）、md、docx、epub
- 导出走后台作业，完成后直接下载

### AI 接入（预留位）

架构方案的原则是「先工具，后智能」，所以 AI 只做接口预留、默认关闭：

- 设置页有独立的「AI 接入」区块：服务商（DeepSeek / Moonshot / 自定义 OpenAI 兼容）、
  接口地址、模型、API Key、温度，以及续写/润色/取名/一致性四项独立开关
- **填了也不会发请求**：当前版本没有安装任何适配器，调用会在网络层之前被拦截
- **API Key 只存本机** `project.json`，界面永远打码显示（`****abcd`）；
  打码值原样回传不会被当成真 Key 写盘
- 将来接入时，AI 产出也只作建议，不会自动改写你的正文

### 手机可用

- 响应式布局：≤ 960px 切换为单栏 + 抽屉 + 底部导航
- 触摸目标 ≥ 40px，输入框 16px（避免 iOS 聚焦时自动放大）
- 适配 iPhone 刘海与 Home Indicator 安全区
- 屏幕边缘向内滑动打开抽屉
- 通过局域网访问，手机上记灵感、读稿、改错字

## 快速开始

**要求 Node.js ≥ 22.18。** 用到 Node 内建的 `node:sqlite`（22.13 起默认可用）和原生 TypeScript 类型擦除（22.18 起默认可用），低于这个版本会直接报错。开发环境为 Node 24。

```bash
git clone https://github.com/shuaixing2020-ux/writing-desk.git
cd writing-desk

npm run serve
```

首次运行会自动安装依赖、构建前端，然后启动服务：

```
写作台 · 本地部署
▸ 启动服务：http://127.0.0.1:7788
```

浏览器打开 **http://127.0.0.1:7788** 即可。首次打开会自动建一个带示例段落的作品，不用面对空白页。

服务端没有编译步骤，`node server/main.ts` 直接跑。

### 分步方式

```bash
npm install       # 安装依赖
npm run build     # 构建前端到 web/dist
npm start         # 启动服务
```

### 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `WD_PORT` | `7788` | 服务端口 |
| `WD_DATA_DIR` | `<项目目录>/data/projects` | 作品数据根目录 |
| `WD_LAN` | 未设置 | 设为 `1` 开放局域网访问（启动日志会打印手机可访问的地址） |

```bash
WD_PORT=8899 npm start
WD_DATA_DIR=~/写作 npm start
WD_LAN=1 npm start   # 手机同 Wi-Fi 可访问
```

开启 `WD_LAN=1` 后，启动日志会列出本机内网地址，手机浏览器直接打开即可：

```
  手机访问（同一 Wi-Fi 下打开下面任一地址）：
    http://192.168.1.101:7788
```

> **局域网安全提示**：局域网模式下没有任何登录与权限校验，同一 Wi-Fi 下的其他人只要知道地址就能读写你的全部稿件。
> 默认只监听 `127.0.0.1`，只在需要时临时开启，不要在公共 Wi-Fi 下使用。

## 你的数据长什么样

每部作品是一个普通文件夹：

```
data/projects/我的小说/
├─ project.json              作品设置（字数口径、每日目标、排版预设）
├─ manuscript/               正文
│  └─ v01-第一卷/
│     └─ c001-开篇/
│        └─ s0001-雨夜.md    ← 一个场景一个文件
├─ bible/                    设定库
│  └─ characters/林远.md
├─ inbox/                    灵感箱
├─ notes/                    笔记（目录预留）
└─ .studio/                  运行时（索引、快照、回收站、导出、备份配置）
   └─ index.sqlite           ← 删掉也没关系，会自动重建
```

一个场景文件长这样：

```markdown
---
id: 01M5X6EBTGXY3H0T28Z0SG9PY2
title: 雨夜来客
order: 1
status: draft
rev: 2
updated_at: 1793056652524
hash: c0a2f84537cdf9ed06cb071a0ec3f4b3
words: 110
---

夜雨敲窗，山门外一片寂静。

“师父，我回来了。”
```

**身份靠 frontmatter 里的 `id`，不靠文件名。** 改名、移动、重排都不会破坏引用。
`.studio/` 整个目录都可以丢弃重建 —— 如果某个数据只能存在这里，说明设计错了。

## 技术栈

| 层 | 选择 | 理由 |
|---|---|---|
| 服务端 | Node.js + 原生 TypeScript | 无编译步骤，`node server/main.ts` 直接运行 |
| Web 框架 | Fastify 5 | 轻量、插件机制清晰 |
| 前端 | 原生 TypeScript + DOM | 无框架、无虚拟 DOM，构建链只有 esbuild |
| 数据库 | `node:sqlite`（Node 内建） | 零依赖、零运维，不需要编译原生模块 |
| 中文索引 | 逐字表 + 锚点校验（SQLite） | 2 字中文词可命中；trigram 分词器做不到 |
| 编辑器 | contenteditable 纯文本 | Markdown 源码可直接编辑，无富文本往返风险 |
| 差异对比 | diff-match-patch | 段落级 + 字符级 |
| 文档导出 | docx 库 + 自写 EPUB 3 打包 | EPUB 用 `node:zlib` 自己打包，零额外依赖 |
| 测试 | `node:test` + Playwright | 单元 + 真实浏览器端到端 |

### 三个刻意的技术取舍

**1. 纯文本编辑器而非富文本**

架构方案原本建议 ProseMirror。实际选择纯文本，因为正文以 Markdown 存储，
富文本需要 HTML ↔ Markdown 双向转换 —— 任何一次转换不完美，都会在保存时静默损坏原文。
「稿件永不丢」是第一原则，所以选了零转换风险的路线。代价是没有所见即所得的格式按钮，
对以叙事文字为主的小说影响很小。

**2. 逐字索引而非 FTS5 trigram**

FTS5 的 trigram 分词器对 2 字中文词（最常见的人名长度）基本失效。
改用逐字建索引 + 锚点校验，任意长度子串都能命中，并能返回位置用于正文定位。

**3. `node:sqlite` 而非 better-sqlite3**

避免原生模块编译 —— 装依赖不需要 C++ 工具链，跨平台少一层坑。代价是 Node 版本要求抬高到 22.18。

## 项目结构

```
writing-desk/
├─ server/                 服务端（Node 原生 TS，无编译）
│  ├─ main.ts              启动入口（REST + WebSocket + 静态托管）
│  ├─ routes/              REST 路由
│  ├─ services/            领域服务（快照/检查/出场/导入导出/备份/索引）
│  ├─ store/project.ts     项目文件夹读写（原子写）
│  ├─ db/index.ts          SQLite 索引与中文搜索
│  ├─ rules/               检查规则包
│  └─ util/                原子写、frontmatter、标点规整、字数、作业队列
├─ shared/types.ts         前后端共享类型（唯一真相）
├─ web/                    前端
│  ├─ src/lib/             API 客户端、状态、DOM 工具
│  ├─ src/components/      外壳、文档树、编辑器、面板、移动端
│  └─ src/styles/          设计令牌与样式
├─ tests/
│  ├─ unit/                单元测试（稿件安全、格式往返、搜索、标点）
│  └─ e2e/                 端到端测试（桌面 + 移动端，真实浏览器）
├─ scripts/                启动、构建、自检、示例数据
├─ docs/                   部署说明、截图
└─ data/projects/          你的作品（已 gitignore）
```

## 开发

| 命令 | 作用 |
|---|---|
| `npm run serve` | 一键启动（自动装依赖 + 构建 + 启动） |
| `npm start` | 只启动服务 |
| `npm run dev` | 启动并监听后端文件变化自动重启 |
| `npm run build` | 构建前端到 `web/dist` |
| `npm run build:watch` | 监听前端源码自动重建 |
| `npm run typecheck` | TypeScript 类型检查 |
| `npm test` | 单元测试（41 项） |
| `npm run test:e2e` | 端到端测试（真实浏览器，16 项） |
| `npm run selfcheck` | 集成自检（30 项，真实起服务跑 HTTP） |
| `npm run seed` | 生成示例作品 |

移动端专项测试（需服务已在 7788 运行）：

```bash
node tests/e2e/mobile-e2e.mjs   # 7 种设备视口 + 抽屉 + 触摸目标 + 手机写作，17 项
```

改动合入前请确保 `typecheck`、`test`、`build` 全绿。
涉及保存逻辑的改动必须额外确认端到端测试里的「刷新后内容恢复」用例通过 —— 那是这个产品的底线用例。

CI 在 GitHub Actions 上跑 Node 22 / 24 矩阵（`npm ci` → `typecheck` → `test` → `build` → `selfcheck`），
外加一个真实浏览器的端到端 job。

代码约定见 [AGENTS.md](AGENTS.md)，贡献流程见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 与同类工具的差异

| | 写作台 | novelWriter | Manuskript |
|---|---|---|---|
| 形态 | 浏览器（本机服务） | 桌面 Qt | 桌面 Qt |
| 手机可用 | ✅ 局域网在线访问 | ❌ | ❌ |
| 存储格式 | Markdown + frontmatter | 纯文本 + 元数据头 | 自有工程格式 |
| 中文优化 | ✅ 字数口径 / 逐字搜索 / 标点检查 / 输入法 | 部分 | 部分 |
| 设定库 | 别名 + 出场识别 | 基础 | ✅ 更完整 |
| 许可 | MIT | GPL-3.0 | GPL-3.0 |

只借鉴了 novelWriter 与 Manuskript 的「文件即真相」思路，未复制其代码。
对比基于各项目公开文档，如有出入以对方项目为准。

## 已知限制

如实说明当前没做的事：

- **导入只支持 txt / md**：docx 导入未实现（导出支持 docx）
- **导出界面只导出整本**：后端支持按卷 / 按章导出，界面还没接上
- **设定库自定义字段**：数据结构与详情展示已支持，新建/编辑表单还没有字段编辑入口
- **笔记（`notes/`）**：目录预留，功能未做；灵感箱是可用的
- **伏笔与时间线**：只有类型定义，功能未实现
- **剧本模式（Fountain）与互动叙事**：未实现
- **手机端是在线形态**：装成 PWA、离线暂存需要 HTTPS 方案，未实现
- **局域网无登录体系**：靠「默认只监听本机 + 显式开启」控制，没有配对令牌
- **单作者**：不做实时协同。多标签页同时编辑用「修订号 + 冲突副本」处理
- **不含 AI（只预留接口）**：设置页有「AI 接入」区块，可以填服务商、模型、API Key，
  但这些配置当前只被记录，**不会发起任何请求**。`AI_ADAPTER_INSTALLED = false`，
  调用会被拦在网络层之前。将来若要真接入，需显式安装适配器并更新
  [AGENTS.md](AGENTS.md) 的红线说明。四项能力（续写/润色/取名/一致性）默认全关
