# 写作台 · 本地部署与使用说明

按《小说写作助手-系统架构方案》落地的本地优先写作工作台。
**数据全部在你自己的电脑上，不联网、不上传、不调用任何 AI。**

---

## 一、启动

### 最快方式

```bash
cd 写作台项目目录
npm run serve        # 或 node scripts/start.mjs
```

首次运行会自动安装依赖、构建前端，然后打印：

```
写作台 · 本地部署
▸ 启动服务：http://127.0.0.1:7788
```

浏览器打开 **http://127.0.0.1:7788** 即可。

### 分步方式（开发时用）

```bash
npm install          # 装依赖
npm run build        # 构建前端
npm start            # 启动服务
```

### 常用命令

| 命令 | 作用 |
|---|---|
| `npm run serve` | 一键启动（自动装依赖 + 构建 + 启动） |
| `npm start` | 只启动服务 |
| `npm run dev` | 启动服务并监听后端文件变化自动重启 |
| `npm run build` | 构建前端产物到 `web/dist` |
| `npm run build:watch` | 监听前端源码，改动自动重建 |
| `npm test` | 单元测试（稿件安全、格式往返、搜索等） |
| `npm run test:e2e` | 端到端测试（真实浏览器跑完整流程） |
| `npm run typecheck` | TypeScript 类型检查 |

### 换端口 / 换数据目录

```bash
WD_PORT=8899 npm start                    # 换端口
WD_DATA_DIR=~/写作 npm start               # 换数据根目录
WD_LAN=1 npm start                        # 开放局域网（见下文安全提示）
```

## 二、数据放在哪

默认：`<项目目录>/data/projects/<作品名>/`

每部作品是一个普通文件夹，**直接用 Finder 打开就能看到全部稿件**：

```
我的小说/
├─ project.json              作品设置（字数口径、每日目标、排版预设）
├─ manuscript/               正文
│  └─ v01-第一卷/
│     └─ c001-开篇/
│        └─ s0001-雨夜.md    ← 一个场景一个文件，Markdown + 元数据头
├─ bible/                    设定库（角色/地点/势力/物品/术语/事件）
│  └─ characters/林远.md
├─ notes/  inbox/            笔记、灵感
└─ .studio/                  运行时（索引、快照、回收站、日志）
   └─ index.sqlite           ← 删掉也没关系，会自动重建
```

**三个重要保证：**

1. **文件即真相**：正文是纯文本 Markdown，用任何编辑器、任何系统都能打开。不锁定格式。
2. **索引可重建**：`.studio/index.sqlite` 只是加速用的缓存。删掉后打开作品会自动重建，不丢任何内容。
3. **可以随时搬走**：整个文件夹拷到 U 盘、放进 iCloud、用 Git 管理都行。

### 备份建议

在「设置 → 备份」里添加一个备份目录（比如外接硬盘），设置保留份数，系统会定期打包整部作品。

也可以直接用系统自带的 Time Machine，或把 `data/projects` 放进 Git：

```bash
cd data/projects/我的小说
git init && git add -A && git commit -m "第一章"
```

因为正文是带元数据头的纯文本，Git 的 diff 会很好读。

## 三、核心功能

### 写作

- **自动保存**：停止输入 2 秒后自动保存；切换章节、切走窗口、关闭页面都会立即保存
- **崩溃恢复**：未确认保存的内容会先写进浏览器本地，服务重启或浏览器崩溃后能找回
- **中文输入法**：拼音组字期间不触发保存与检查，不会吞字、跳光标
- **字数口径**：三档可切换（仅汉字 / 汉字+标点 / 平台口径），状态栏常显
- **专注模式**：`Cmd/Ctrl+Shift+F` 隐藏所有面板
- **打字机模式**：光标行固定在屏幕中央

### 结构

卷 → 章 → 场景三级，可拖拽排序、折叠、改状态（构思/草稿/修改中/定稿/已发布）。
每个场景可写摘要，大纲面板里可见。

### 设定库

角色、地点、势力、物品、术语、事件六类，支持别名和自定义字段。
正文里出现的名称会被识别，条目页能看到「出现在哪些章节、几次、首次与最近出场」。

### 检查（不依赖 AI）

标点规范（引号不成对、省略号/破折号写法、重复标点、全半角混用）、常见错别字、
相邻重复词、句首重复、段落过长、对白引号风格混用。
每条规则可单独开关，结果可逐条忽略。

### 版本与安全

- 自动快照（按时间 + 重大操作前）
- 任意两个版本可做差异对比（段落级 + 字符级）
- 恢复到任意历史版本，恢复前会先给当前版本存一份快照
- 删除进回收站，可恢复

### 导入导出

- 导入：txt（自动切章，先预览确认）、md、docx
- 导出：txt（可套用平台排版预设）、md、docx、epub
- 范围：全书 / 某卷 / 某章

## 五、手机访问

### 布局

界面在 ≤960px 自动切换为移动形态：

- **单栏**：正文占满屏幕，去掉桌面的大边距
- **抽屉**：左侧稿件树、右侧面板改为滑出式抽屉，从屏幕边缘向内滑动可打开
- **底部导航**：稿件 / 搜索 / 保存 / 面板 / 灵感 五个入口，拇指可达
- 触摸目标 ≥40px，输入框 16px（避免 iOS 聚焦时自动放大）
- 适配 iPhone 刘海与底部 Home Indicator 安全区
- 弹窗改为底部弹出式，手机上更好够到

平板上同理（≤960px）。横屏手机会压缩顶栏与导航高度。

### 连接

1. 手机和电脑连同一个 Wi-Fi
2. 用 `WD_LAN=1 npm start` 启动，服务会监听局域网地址
3. 启动日志会打印手机可访问的地址（形如 `http://192.168.x.x:7788`）
4. 手机浏览器打开即可

> **安全提示**：局域网模式下，同一 Wi-Fi 下的其他人只要知道地址就能读到你的稿件。
> 默认只监听本机（`127.0.0.1`），只在需要时临时开启。
> 不要在公共 Wi-Fi 下开启。
>
> 手机端目前是「在线使用」形态。安装成 App、离线暂存需要 HTTPS，
> 属于架构方案 7.9 的后续工作。

### 移动端测试

```bash
node tests/e2e/mobile-e2e.mjs    # 需服务已在 7788 运行
```

覆盖 7 种设备视口（iPhone SE / 14 Pro / 14 Pro Max / Pixel 7 / iPad Mini / iPad Air / 笔记本）、
抽屉开合、底部导航、触摸目标尺寸、手机实际写作与保存、刷新恢复。

## 六、故障排查

**打不开页面**
```bash
# 确认服务在跑
curl http://127.0.0.1:7788/api/projects
```
如果没输出，看终端里的报错。端口被占用就换一个：`WD_PORT=8899 npm start`。

**页面白屏 / 功能异常**
```bash
npm run build      # 重新构建前端
```

**索引坏了 / 搜索结果不对**
在「设置 → 维护」里点「重建索引」，或直接删掉作品的 `.studio/index.sqlite` 后重新打开作品。
**不会丢任何正文**——索引是从文件重建的。

**想确认稿件真的没丢**
打开作品文件夹，用任何文本编辑器打开 `manuscript/` 下的 `.md` 文件。
如果那里有内容，就永远没丢。

**升级后打不开旧作品**
`project.json` 里有 `schema_version`，升级会自动做整项目备份再迁移。
备份在 `.studio/backups/`。

## 七、技术说明

| 层 | 选择 | 说明 |
|---|---|---|
| 服务端 | Node.js 24 + 原生 TypeScript | 无需编译步骤，`node server/main.ts` 直接跑 |
| Web 框架 | Fastify 5 | 轻量、插件机制清晰 |
| 前端 | 原生 TypeScript + DOM | 无框架、无虚拟 DOM，构建链只有 esbuild |
| 数据库 | `node:sqlite`（Node 内建） | 零依赖、零运维，无需编译原生模块 |
| 中文搜索 | 逐字索引 | 2 字人名也能搜到（trigram 分词器做不到） |
| 编辑器 | contenteditable / 纯文本 | Markdown 源码可直接编辑，无富文本往返风险 |
| 移动端 | 响应式 CSS + 抽屉 + 底部导航 | ≤960px 切换单栏，触摸目标 ≥40px |
| 端口 | 默认 7788，仅本机 | `WD_LAN=1` 才开放局域网 |

### 为什么不用富文本编辑器

架构方案原本建议 ProseMirror/Tiptap。实际落地选择了纯文本编辑，理由是：

正文以 Markdown 存储，富文本编辑器需要「HTML ↔ Markdown」双向转换。
任何一次转换不完美，都会在保存时静默损坏作者的原文。
**稿件永不丢是最高优先级**，所以选了零转换风险的那条路。

代价是没有所见即所得的加粗/斜体按钮。对小说写作而言这个代价很小——
正文以叙事文字为主，格式需求只有段落和少量强调。

### 项目结构

```
小说辅助工具/
├─ server/                 服务端（Node 原生 TS）
│  ├─ main.ts              启动入口
│  ├─ routes/              REST 路由
│  ├─ services/            领域服务（快照/检查/搜索/导入导出/备份）
│  ├─ store/project.ts     项目文件夹读写（原子写）
│  ├─ db/index.ts          SQLite 索引
│  ├─ rules/               检查规则包
│  └─ util/                原子写、frontmatter、字数、作业队列
├─ shared/types.ts         前后端共享类型（唯一真相）
├─ web/                    前端
│  ├─ src/lib/             API 客户端、状态、DOM 工具
│  ├─ src/components/      外壳、文档树、编辑器、面板
│  └─ src/styles/          设计令牌与样式
├─ tests/                  单元测试 + 端到端测试
├─ scripts/                启动与构建脚本
└─ data/projects/          你的作品（默认位置）
```
